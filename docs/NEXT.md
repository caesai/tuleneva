# На будущее

Чеклист сервера: [VPS.md](VPS.md).

Вход пользователей — Telegram Mini App и инвайт. Формы почты скрыты, пока не задан `VITE_EMAIL_AUTH_UI=true`. В общем чате `/today` и `/tomorrow` показывают только занятые интервалы, без имени и коллектива.

## Дальше

1. **Привязка почты у своих.** Зарегистрированному пользователю без почты при входе в Mini App показать окно с предложением добавить почту. Если закроет, не добавляя, окно не показывать до следующего раза. Пока это не включено для всех, формы остаются за `VITE_EMAIL_AUTH_UI`.
2. **OAuth / phone.** В контракте и модели пользователя enum уже есть, маршрутов нет. Делать, когда будет выбран провайдер. Сейчас не нужно: круг лиц закрытый, вход через Telegram.

## Админка студии

По каждому пункту отдельно план, потом код. Живые данные по-прежнему в Mongo на VPS. Коллекции: пользователи, брони (`Rehearsal` — один документ на день), инвайты, журнал смен ролей.

1. **Локальная копия.** Две отдельные вещи, нового входа не писать.
   - **Управление с машины.** `npm run dev` уже ходит в Mongo на VPS (`/api`, `/ws`). Админ один раз в Mini App задаёт себе почту и пароль и подтверждает письмо (нужен SMTP). Дальше локально: `VITE_EMAIL_AUTH_UI=true npm run dev`, вход по почте в браузере на `https://tuleneva.local`. JWT тот же пользователь, что и в Telegram. `VITE_ADMIN_ID` не использовать: клиент по нему сессию не получает. Инвайт `provider: web` создаёт нового пользователя, для этого входа не подходит.
   - **Запас на диске.** Дамп — [server/scripts/backup-mongo.sh](../server/scripts/backup-mongo.sh) и [VPS.md](VPS.md) §8. Копию скачивать к себе. Второй рабочей базы нет: правки только в живую Mongo через этот вход.
   - **Код (сделано).** Форма привязки своей почты у admin/super_admin без `VITE_EMAIL_AUTH_UI`; модалка сброса пароля по `?passwordReset=` без флага. SMTP, DNS почты (TXT/MX у хостинга) и cron дампа — руками на VPS.
2. **Статистика броней.** Считать по уже сохранённым слотам: занятость по дням и месяцам, часы, кто и сколько бронировал. Графики — в админке. Это статистика броней, отдельного учёта «пришёл / не пришёл» нет.
3. **Закрытый день.** Админ создаёт событие на день, когда в здании работы и бронировать нельзя. Новые брони на этот день не проходят. День виден в расписании и в боте (`/today`, `/tomorrow`). Пользователи с Telegram получают оповещение. Уже стоящие на этот день брони админ видит и решает сам; автоматической отмены нет.
